THE SHORT VERSION

Five ideas, connected to the code

Read one, change the code, then try it in the chat.

01

What is a language model?

A model predicts likely next pieces of text from patterns learned during training. It is not a search engine or a database of guaranteed facts.

reply = model(messages)
02

Prompt vs. system instruction

Your prompt is the task you ask for. A system instruction is the higher-level behavior you set first, such as “be a patient tutor.”

role: "system"
03

Tokens

Models read text as tokens: small chunks of words or characters. More tokens usually means more context and more compute.

estimateTokens(text)
04

Context across turns

The model does not automatically remember this chat. Your app sends earlier user and assistant messages again in conversation.

...conversation
05

Why can it make things up?

Because it generates plausible language, it can sound confident while being wrong. Add a knowledge source, citations, and an “I’m not sure” path.

if (!sure) say_so

NEXT LAYER

Same interface, different engine

In a real app, the input form can call your server. The server adds a system instruction, forwards the conversation to a model, and returns the generated text. The demo below shows the request shape without asking you for a secret key.

browser→your server→language model

Why a server? API keys belong on the server, not in browser code that anyone can inspect.
